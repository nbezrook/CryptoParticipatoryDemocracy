# Common Ground · Cooperative Federation Lab

A reproducible simulation presented as an interactive scientific working paper. Six consumer councils propose consumption baskets; a farm, bakery, and energy cooperative operate within shared resource constraints. Indicative prices guide proposal revisions, while a separate proportional allocation rule enforces feasibility.

This is a research starting point, not a complete implementation of participatory economics. No cryptocurrency, wallet, blockchain, or cryptographic proof is implemented yet.

## Run the dashboard

Requires **Node.js 22 or newer**. No third-party packages, accounts, services, or installation step are required.

```sh
cd /workspace/CryptoParticipatoryDemocracy
npm start
```

The server listens on port **3000**, bound to the local machine by default. Set `PORT` if that port is occupied. The dashboard runs entirely in the browser and uses the same model module as the command-line simulator. It does not send scenario data to an external service.

Use the supply scenarios and sliders to rerun the model. Open **Random seed & numerical parameters** to change the random seed and adjustment rate. Scrub the timeline or press Play to inspect the planning rounds. The initial view shows the last completed round.

- **Resource trajectories:** proposals relative to available capacity. Values above 100% are excess demand, not allocated resource use.
- **Resource balance:** proposed and actually allocated quantities, with the corresponding physical limits.
- **Council allocations:** goods received and an initial-basket quantity index.
- **Indicative prices:** accounting signals generated by scarcity premiums, not prices on a simulated trading market.
- **Export run:** complete JSON including model version, configuration, preferences, capacities, and every round.
- **Import run:** reproduce a dashboard export from its configuration. Saved outcome data is recomputed, not trusted. Configurations outside the dashboard's ranges can be reproduced with the model module.
- **Export CSV:** one row per round, for plotting or analysis elsewhere.
- **Print article:** a manuscript layout with figures, equations, references, the numerical appendix, and the current experiment parameters; interactive controls are omitted from the printed document.

## Reproduce and test an experiment

```sh
npm test
mkdir -p artifacts
node scripts/simulate.mjs --seed 42 --scenario baseline > artifacts/baseline.json
node scripts/simulate.mjs --seed 42 --scenario energy --shock 30 > artifacts/energy.json
node scripts/simulate.mjs --seed 42 --scenario harvest --shock 30 --csv > artifacts/harvest.csv
```

Run the command directly with `node` when redirecting output: `npm run` adds a script banner to stdout. Additional flags: `--rounds`, `--credits`, and `--rate`. Invalid arguments fail with a nonzero exit status. A valid simulation that reaches its round limit still exports its results; check `outcome` before describing it as converged.

Exact replay of an exported configuration:

```js
import { readFile } from 'node:fs/promises';
import { simulate } from './src/model.js';

const saved = JSON.parse(await readFile('artifacts/baseline.json', 'utf8'));
const replay = simulate(saved.config);
// With the same model version, replay reproduces the full deterministic result.
```

The tests check reproducibility, capacity and budget constraints across seeds and shocks, documented scenario convergence, explicit round-limit reporting, and CSV/export replay. They do not establish economic realism or incentive compatibility.

An optional functional browser check is provided as `python scripts/browser-smoke.py`. It requires Python Playwright and Chromium, with the development server running. It exercises scenario controls, playback, export/import, exact browser-to-Node replay, and responsive layouts, and saves screenshots in `artifacts/`. Use `BROWSER_EXECUTABLE` to select an installed Chromium executable, and `SIMULATION_URL` if using a different port. These tools are not needed to run the simulator or dashboard.

## Default experiment

Seed 42, 9 credits per member, adjustment rate 1.2, maximum 160 updates, and a 0.8% convergence tolerance:

| Supply scenario | Updates to convergence | Final highest constraint residual |
| --- | ---: | ---: |
| Steady state | 10 | 0.569% |
| 30% electricity reduction | 10 | 0.647% |
| 30% farm and grain reduction | 15 | 0.710% |

Round zero is recorded before any price update. A run with 10 updates therefore contains 11 snapshots. A converged run can retain a small amount of rationing within tolerance; actual allocations always satisfy the physical constraints.

Convergence can also result from smaller consumption proposals as indicative prices rise. **A feasible plan does not establish that people's needs are met.** The dashboard makes consumption reductions visible instead of treating convergence as a welfare result.
